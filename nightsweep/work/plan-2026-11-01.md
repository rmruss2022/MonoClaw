## Suggestions for tomorrow
1. **Lock down mock-stick pairing (security, P0).** `/stick/pair/begin` accepts *any* `code` from the caller when `stickId === "stick-mock"`. Pairings are saved with `INSERT OR REPLACE` keyed by code, so anyone can overwrite a real TV's pending pairing code. The owner then pairs the mock stick instead of their TV, and the attacker's browser gets the casts. Only allow `"000000"` (fixed tonight, see below). Then consider hiding `/mock` behind an env flag in production, since every account that claims `000000` shares one `stick-mock`.
2. **Commit the router WIP** (`mockStick.ts`, `remoteCtrl.ts`, index/sessions changes), redeploy the router on Railway, and test end to end: `/remote` login → search → cast → the `/mock` tab shows the title.
3. **Check `/remote/login` for abuse.** It's an open proxy for password attempts against the cloud `/api/login`. Add a simple per-IP rate limit, and confirm the cloud service has its own limit.
