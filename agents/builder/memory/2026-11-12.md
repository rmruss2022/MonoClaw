
## openhome voice: AEC + Speex NS (mic over music)
Goal: wake word "Hey Jarvis" reliable while music plays on X10.
- **Speex noise suppression**: openWakeWord 0.4.0 `Model(enable_speex_noise_suppression=True)`. Needs pkg `speexdsp_ns` — NO pypi wheel; build from source: `sudo apt install libspeexdsp-dev swig` + `pip install Cython` + `pip install git+https://github.com/TeaPoly/speexdsp-ns-python.git`. Toggle via env SPEEX_NS (default 1).
- **AEC (PipeWire module-echo-cancel, webrtc)**: config `~/.config/pipewire/pipewire.conf.d/99-echo-cancel.conf` on Pi. Creates virtual nodes `echo_cancel.source` (clean mic = A21 minus music) + `echo_cancel.sink` (music reference). `webrtc.delay_agnostic=true` for Bluetooth drift. capture target=`alsa_input.usb-Generic_AIRHUG_21_AIRHUG_21-00.analog-stereo`, playback target=`bluez_output.F4_4E_FD_49_83_98.1` (X10).
- **Soloist repoint**: edited `~/.config/systemd/user/openhome-soloist.service` ExecStart `--pipewire-device bluez_output.F4_4E_FD_49_83_98.1` → `echo_cancel.sink` so music feeds the AEC reference (.bak saved). daemon-reload + restart.
- **voice_client capture**: new env `MIC_PW_SOURCE=echo_cancel.source` → open_mic uses `pw-record --target echo_cancel.source --rate 16000 --channels 1 --format s16 --raw -` instead of arecord. Frees A21 ALSA hw so WirePlumber can expose it to the module. Fallback to arecord if env unset.
- **DUCK_LEVEL 8→20** (wake-listen music level ~20%, not near-silent). **skip clip fix**: fast_intent skip sleeps 0.45s (ducked) after `soloist ctl next` before un-duck.
- **GOTCHA**: restarting pipewire orphans a running soloist (reports "playing" via Connect but no stream) AND the old voice client's arecord holds A21 exclusively (Subdevices 0/1) blocking the mic node. Order: stop voice → frees A21 → alsa_input node reappears → start soloist → start voice. Also a stray soloist can hold ws port 3680 → new instance exits 1; pkill it.
