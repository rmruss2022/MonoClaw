## OpenHome "no endpoint found" + Spotify routing FIX (Nov 8)
- **Architecture:** librespot runs per-room (`--name "openhome · Living Room" --backend pulseaudio`) = Spotify Connect source → feeds PipeWire. The hub's `pwRouter.ts` (PipeWire router, NOT snapcast — snapcast inactive) is the intended path: route librespot's output to whichever BT-speaker sink a room maps to via `wpctl set-default`. The `route-output` cmd uses it; `play-in-room` did NOT (it used the Spotify-Connect `spotify.deviceForRoom` path → "No endpoint for {room}" because Spotify API doesn't list the librespot device until "played once").
